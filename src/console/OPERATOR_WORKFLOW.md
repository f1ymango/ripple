# Saved comparisons, briefings and operator decisions

The console consumes the unchanged plan, result, briefing and audit contracts
in [the architecture](../../docs/03-architecture.md). D/F producer paths and
checks are documented in [the Lead handoff](../../docs/lead-pipeline-handoff.md).

Point G at D's saved plan bundle, E's results and F's saved drafts:

```bash
RIPPLE_PLANS_DIR=data/generated-plans/IN-26-03365-first \
RIPPLE_RESULTS_DIR=results/runs \
RIPPLE_BRIEFINGS_DIR=data/generated-briefings \
streamlit run src/console/app.py
```

Those environment variables also work on Windows; set them with PowerShell's
`$env:RIPPLE_PLANS_DIR = "data/generated-plans/IN-26-03365-first"` syntax.
No model or simulator is called by the console.

Each comparison needs matching P0/P1/P2 results and their original
`<run_id>.provenance.json` sidecars. D's plans directory must include the saved
`generation-inputs.json`. G revalidates D's constraints and E's provenance;
compared runs must identify identical shared simulation inputs. P0 must meet
the GEH and speed validation targets. Missing or changed artifacts withhold
the recommendation. The lowest simulated delay wins, including P0. These
checks do not replace C/E review of model acceptance.

F's briefing must match the winning run/plan, all comparison result and sidecar
sources, sign IDs and message limits. The panel offers English and Traditional
Chinese. An identified operator can record approval or rejection with a note.
Message delivery is manual.

G appends the existing `viewed`, `approved` and `rejected` audit fields to
`evidence/audit_log.jsonl`. Notes retain the displayed evidence fingerprint.
Identified views are recorded once per draft and operator in the session.
Inputs are re-read before each action; changed inputs require another review.
Set `RIPPLE_AUDIT_LOG` to use another path.

Audit writes use a persistent sibling `.lock` file: `msvcrt` locks byte zero
on Windows; `fcntl` locks the file on Unix. The lock covers opening the audit
file, writing the full UTF-8 record, flushing and syncing it. Lock failures
raise before writing; Windows reports failure after its bounded retry period.
Keep the lock file in place. All writers must use this append function.

The focused Windows CI job runs real Streamlit startup, approval/rejection,
UTF-8 audit and competing-process locking tests with named mock artifacts.
Synthetic traffic fixtures remain under `tests/fixtures/mock_recommendation/`.

## Synthetic approval rehearsal

Run `streamlit run src/console/fixture_demo.py --server.port 8505` to show the
briefing and audit controls with the existing mock P0/P1/P2 bundle. A persistent
purple badge and warning identify the fixture throughout the screen recording.
The helper copies the source fixtures verbatim to the ignored
`tests/fixtures/mock_operator_capture/` directory; the contract-required
`generation-inputs.json` basename is kept inside that mock directory. It writes
its audit only to `mock_audit_log.jsonl` there. The helper preserves any
existing copied artifacts, so a changed result continues to fail validation
instead of being silently refreshed. The rehearsal never writes a real result,
briefing or audit record and never calls a model or simulator.
